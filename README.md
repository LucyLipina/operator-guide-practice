# Практическая работа 16. Разработка руководства оператора

Учебный сервис заявок, интерфейс **1.5.0**, спецификация **SPEC-1.0**.
Все данные синтетические. Скриншоты не имитируются.

## Источники
- `data/service_spec.md` — спецификация SPEC-1.0 (бизнес-правила, лимиты).
- `data/operator_observations.md` — текстовые наблюдения интерфейса 1.5.0.
- **Figma-макет:** [«Учебный сервис заявок • оператор и техник»](https://www.figma.com/design/RjTPhmlThjW9P0F0IAoEEQ/%D0%A3%D1%87%D0%B5%D0%B1%D0%BD%D1%8B%D0%B9-%D1%81%D0%B5%D1%80%D0%B2%D0%B8%D1%81-%D0%B7%D0%B0%D1%8F%D0%B2%D0%BE%D0%BA-%E2%80%A2-%D0%BE%D0%BF%D0%B5%D1%80%D0%B0%D1%82%D0%BE%D1%80-%D0%B8-%D1%82%D0%B5%D1%85%D0%BD%D0%B8%D0%BA?node-id=3-371) (версия 1.5.0, node-id 3-371). Использован для визуальной сверки расположения элементов, названий кнопок и состояний форм.

## Аудитория руководства
- оператор (`operator_a` / `operator_b`) — создаёт и проверяет свои заявки;
- техник (`technician_a`) — работает с назначенными заявками.

Административные действия (назначение исполнителя, развёртывание, миграции) в руководство не входят — для них предусмотрено обращение в поддержку.
